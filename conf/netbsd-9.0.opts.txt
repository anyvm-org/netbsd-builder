# wait screen text  | press key | timeout seconds
#
# EVERY line must carry the third (timeout) column. build.py's waitForText()
# treats an empty timeout as "wait forever", so a single unbounded line turns
# any guest that dies mid-install into a job that spins "(no new screen text)"
# until the 6 h CI ceiling or a human kills it. That is not hypothetical: these
# 9.x/10.x kernels take random fatal page faults on the runners' KVM (2026-07-26
# a 9.2 hit "prevented execution of 0x0 (SMEP)" and burned 2 h; 2026-07-27 a 9.1
# dropped into DDB at "Stopped in pid 1.1 (init)" and burned 3.5 h -- that one
# had a bounded FIRST line, then hung on the unbounded SECOND one instead).
# With every line bounded, a dead guest fails the build in minutes and rerun.yml
# retries it automatically.
#
# Values are deliberately generous, not tight: a timeout here is a crash
# backstop, not a performance budget. Observed times on a healthy VNC+OCR run
# are 4-20 s per menu step and ~110 s for set extraction, so 300 s / 1800 s
# leave >10x headroom while still bounding the failure.

# First wait also covers the ISO boot (~87 s observed).
